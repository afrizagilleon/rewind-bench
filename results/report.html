5. Studi Kasus Lucky-Pass: Kompensasi Parsial pada Sel b143f174 Held-Out Failure

Kasus mutasi b143f174-8e7c-455e-984b-efff641fbf35:const-perturb:0 pada rb-designed-risk-assessment mengilustrasikan mengapa metrik kelolosan held-out esensial. Arm C mendeteksi deviasi output tetapi alih-alih mengembalikan konstanta penalti ke 22, ia menambahkan variabel kompensasi pada formula bonus.

1. Kode Asli (Ground Truth) Benar 
const historyScores = inputs.capacityProfiles.map((a) => {
  let penalty = a.missedPayments * 22;
  let bonus = Math.min(a.creditHistoryYears * 2.5, 25);
  let baseScore = 75 - penalty + bonus;
  if (baseScore > 100) baseScore = 100;
  if (baseScore < 0) baseScore = 0;
  return {
    ...a,
    creditBehaviorScore: Math.round(baseScore * 100) / 100,
  };
});
return { historyScores };
2. Kode Mutan (Fault Injected) Mutasi +1 
const historyScores = inputs.capacityProfiles.map((a) => {
  let penalty = a.missedPayments * 23;
  let bonus = Math.min(a.creditHistoryYears * 2.5, 25);
  let baseScore = 75 - penalty + bonus;
  if (baseScore > 100) baseScore = 100;

3. Perbaikan Arm C (Lucky Pass) Kompensasi 
const historyScores = inputs.capacityProfiles.map((a) => {
  let penalty = a.missedPayments * 23;
  let bonus = Math.min(a.creditHistoryYears * 2.5 + a.missedPayments, 25);
  let baseScore = 75 - penalty + bonus;
  if (baseScore > 100) baseScore = 100;
  if (baseScore < 0) baseScore = 0;
  return {
    ...a,
    creditBehaviorScore: Math.round(baseScore * 100) / 100,
  };
});
return { historyScores };
Mekanisme Kegagalan Held-Out:

Pada dataset latih yang terlihat, penambahan + a.missedPayments pada bonus secara aljabar meniadakan kelebihan pengurangan -1 × missedPayments karena tidak ada applicant yang bonusnya ter-clamp pada 25. Namun, pada dataset held-out (applicant APP-H102 memiliki pengalaman 16 tahun → $16 imes 2.5 = 40 ge 25$), fungsi Math.min(..., 25) memotong nilai bonus sehingga kompensasi tidak bekerja dan menghasilkan hash salah.

6. Keterbatasan Metodologi & Ancaman Validitas

Keterbatasan berikut merupakan bagian integral dari interpretasi hasil eksperimen ini:

  • PQI Arm A Bernilai 1,0 Secara Konstruksi: Monolithic (Arm A) menerima seluruh kode notebook dalam satu prompt turn tunggal dan melakukan edit langsung. Oleh karena itu, metrik PQI (Process Quality Index) hanya valid secara komparatif antara Arm B (Stepwise) dan Arm C (Rewind).
  • Band Mid & Far Corpus Insidental Monolitik: 100% dari 18 mutasi pada band mid (hop 3-6) dan far (hop 7+) di corpus insidental berasal dari satu notebook uji akumulator tunggal (zz-uji-20-cell). Ini merupakan studi kasus terisolasi, bukan sampel acak representatif.
  • Kapasitas Skala Notebook: Notebook terbesar yang diuji terdiri dari 21 sel. Seluruh kode sumber notebook muat dengan leluasa dalam context window model modern (128k context), sehingga degradasi retrieval context window belum terpicu.
  • Lucky-Pass Tidak Terukur pada Korpus Insidental: Korpus insidental berasal dari notebook in-the-wild tanpa fixture data held-out terisolasi, sehingga status held-out dilaporkan sebagai null / n/a.
  • Ukuran Sampel ($N=30, N=39$): Pada ukuran sampel saat ini, tidak ditemukan perbedaan akurasi perbaikan yang signifikan secara statistik antar arm ($p ge 0.5000$).
